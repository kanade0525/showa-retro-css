# 意匠の一括検分

**利用者に不具合を探させないための手順です。** 一件ずつ指摘させて一件ずつ
直すやり方は一度やって丸一日溶かしました。まとめて撮り、まとめて見て、
まとめて直します。

## 1. 撮る

```sh
npm run shots            # 昼夜。3〜4分かかる
npm run shots -- --light # 急ぐとき
```

`docs/review/` に節ごとの PNG と一覧ページができます。

## 2. 機械で分かるものを先に落とす

```sh
npm run check   # 静的。CI でも回る
npm run audit   # 描画して実測。合成ボールドと端末依存フォント
```

生成物の陳腐化・コントラスト表・存在しないクラス・混植は、ここで出ます。
**人が探す必要はありません。** ここで落ちたものは検分の対象外にします。

## 3. 節ごとに並列で検分する

`ishou-reviewer` を**節の数だけ並列に**起動します。一つの agent に
一節だけ渡してください。まとめて渡すと精度が落ちます。

各 agent に渡すもの:

- 節の id とタイトル
- 画像のパス（昼・夜、あれば狭い画面）
- 「`index.html` と `src/*.css` を必要に応じて読んでよい」

節の一覧は `docs/review/index.html` か、`index.html` の `<section id>` から
取れます（18節）。

## 4. 選別する

agent の報告をそのまま利用者に流さないでください。**確度「確実」のものと、
「疑い」でも自分で確かめて裏が取れたものだけ**を残します。

裏の取り方:

- 描画を自分で Read して見る
- computed style を測る（Chrome の `--dump-dom` に仕込む）
- 寸法・重なりを数値で出す

**「効いたか」ではなく「結果が正しいか」を測ること。** ここを飛ばして
「直した」と報告した失敗が何度もあります。

## 5. まとめて直して、一度に出す

```sh
git switch -c fix/ishou
# …直す…
npm run build && npm run check
npm run shots -- --light   # 直った所と、壊していない所を確認
```

一件ごとに tag / release / デプロイをしない。

## 判断の基準

### 消すのは答えではないことが多い

「宙に浮いて見える」なら、**浮かない置き方**にするのが筋です。部品を消すのは、
**重複しているか、意味が無い**ときだけ。

- 判子（店先）… 重複かつ意味なし → 削除が正解だった
- 袖看板（店先）… 再現の質の問題 → 削除は誤り。画面の縁で切って
  「画面外へ続く壁から突き出している」と読ませて解決した

### 実物の要件（考証台帳）

**ここに書いていないことは、次の会話では失われます。** 新しく分かったら必ず追記。

#### 文字組

| 項目 | 要件 |
| --- | --- |
| 訂正線 | **字を跨ぐ。**足元に引くと下線になる（フォントの `yStrikeoutPosition` に任せない） |
| 袋文字 | 縁は**外に出る**。`-webkit-text-stroke` は中心振り分けなので指定の半分しか外に出ない |
| 長体・平体 | **組み幅そのものが詰まる。**`transform` だけでは箱が残って後ろに空きが出る |
| 二重縁取り | **同心の縁が2本。**右下の影は縁ではない |
| 標語 | 「**火の用心**」。「火の元用心」は誤り |


#### 強制配色（Windows ハイコントラスト）

**前提を取り違えて一度作り直しました。** 実測した挙動はこうです。

| 描き方 | 強制配色での扱い |
| --- | --- |
| `linear` / `radial` / `repeating` / `conic-gradient` | **描かれない**（勝手に落ちる） |
| `url("data:image/svg+xml,…")` | **作者の色でそのまま残る** |
| `background-color` | Canvas に置換 |
| `box-shadow` / `text-shadow` | none に強制 |
| CSS三角（`border-color: X transparent …`） | 4辺とも CanvasText になり**塗り潰しの四角** |

- `background-image: none` は**SVGにだけ必要**。グラデーションには無意味
- **`forced-color-adjust` は継承する。** ①の中に入る②部品には `auto` で戻す
- **グラデーションで描いた「意味を持つ線」は引き直す**（目盛りの値・選択の矢印・
  訂正線・升目・罫）。落ちると情報そのものが消える
- 撮影は `npm run shots -- --forced`。**夜との組み合わせも撮る**こと
- Chrome の `--force-high-contrast` は**暗い系統色しか出さない**。明るいテーマで
  淡色の部品（蛍光灯・ネオンの芥子）が飛ぶ可能性は未検証

#### 作例（部品を組むとき）

- **壁に付く物・置く物・吊る物・紙に押す物を混ぜない**
- 一枚の中で**場所を混ぜない**（茶の間・店先・駅を同居させない）
- 画面内の**時刻・日付・文言が互いを否定しない**こと
- **寸法の比**を守る（マッチとお品書きは3〜4倍差）

### 見落としやすい型

1. **指定が効いていない** — 要素既定に負ける（`code` `pre` `input`）、
   詳細度に負ける（`.d-sode` の `position` が `.sw-sodekanban.is-udegane` に負けた）
2. **合成ボールド** — レトロミンは 400 のみ。太字要求で偽の太字
3. **夜間モードのコントラスト** — 地色がテーマ変数＋文字色が物体色は潰れる。
   `:hover` を忘れない
4. **実物として成立しない配置** — 部品が正しく描けていることとは別問題
5. **意味のない飾り** — 部品を意味なく置いていないか
